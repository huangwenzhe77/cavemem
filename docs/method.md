# CAVE-Mem 从历史失败到在线决策

CAVE-Mem 的控制器学习一次提醒相对于执行原动作的增量价值，解决任务的 Qwen2.5-7B 权重固定。下表对应研究草稿的方法与调用入口。

| 草稿 | 实现与实际用途 |
|---|---|
| §2.1、§3.1，式 1、6 | 历史无记忆轨迹生成后，教师以历史成功轨迹为参照，在失败轨迹选点，给出替代动作、机制、可观测条件和提醒。源验证从同点恢复，用 K 个独立续跑种子比较原动作、替代动作、文字提醒。每个种子内共享对应步的随机数，记录每臂终局和成本。两种干预各自的配对净收益区间下界均大于零时入库。卡片携带源动作、适用和排除规则、证据路径与哈希、质量估计。K 默认为 3，小样本近似 t 区间只描述该检查点。代码见 `alfworld_memory.build_bank`、`verify_replicates`。 |
| §2.1、§3.2，式 2 | 在线先封存原动作、公开观察、允许动作和状态摘要，再取至多一条符合条件的记忆。可观测特征包括证据效度、目标适用性、原动作是否符合建议或吻合源失败签名、未知暴露、源目标动作菜单差异、访问历史差异、剩余预算和源端证据质量。代码见 `alfworld_controller.collect_one/assess/vector`。 |
| §2.2、§3.3，式 3–5 | 目标训练默认按同点两臂续跑。沉默执行缓存动作，提醒多付一次重拟成本，随后回到同一冻结 actor。真实终局、token、环境步数和时间计算 D 和配对回归 H。运行时抽点记录条件概率及首个命中概率，训练时原动作已符合建议的点有更高采样概率，验证与测试用预登记的统一采样率。 |
| §4.1，式 7 | 训练监督 MLP 净收益头、折外校准的回归风险头和额外 token 预测器。配对实测结果给二元策略提供监督热启动。类别不足时，风险预测器显式返回证据不足。代码见 `intervention_policy.train/supervised_start` 和 `auxiliary_heads.fit_heads`。 |
| §4.2–4.3，式 8–14 | 可克隆时以配对 D 优化策略；选择单臂时原地随机分配，每点只有一个终局，保存真实倾向概率，以任务折外交叉拟合的 DR 分值训练。单臂风险按可能回归的保守上界处理。策略从监督模型出发，实际更新 MLP、KL 惩罚及风险和资源约束的对偶变量。验证收益和预算后冻结，证据不足时沉默。代码见 `intervention_policy.train/calibrate/decide` 和 `constrained_gate.optimize`。 |
| §4.4，式 15 | 可选的独立诊断队列先随机沉默、提醒或只读检查，检查后再随机分配。观察只给门控。依据带成本的序贯估值、信息价值下界、独立风险和成本校验决定是否启用。在线每题至多一次检查。代码见 `alfworld_controller.probe_fit/select`、`probe_value.estimate`。 |
| 算法 1 最终决策 | `alfworld_experiment.deploy` 读取冻结产物并核对来源，现场运行 actor。门控的决定直接控制下一步。部署每题只支付实际所选动作的开销。配对审计另存，可统计救回、致败、双成功额外开销及任务级区间。 |
| §5 实验设计 | mini 开发环境包含适用性×动作暴露四格、噪声库、消融、同预算配对与单臂训练、组件基线、第二 actor 参数。ALFWorld 支持模板隔离、可选任务族和源失败签名留出，以及相同检查点上沉默、匹配即提醒、暴露规则、监督和约束策略比较。实际部署结果与配对回算分别报告。 |

## 在新目录调用整条流程

在仓库根目录安装项目并配置教师 API 后执行。登记文件包含样本、成本、预算、代码和权重指纹。再次执行同一命令时复用已完成的阶段。

```bash
python -m memory_agent.cave.alfworld pipeline \
  --out outputs/cave-alfworld-v2 \
  --data /path/to/alfworld-data \
  --config /path/to/alfworld/configs/base_config.yaml \
  --weights /path/to/Qwen2.5-7B
```

`--single-arm` 选择随机单臂训练和验证；`--inspect-per-family N` 登记独立的两阶段诊断游戏。各 split 的 `--*-per-family` 控制数据量。默认小队列用于流程检查，不能满足严格校准所需的样本量，门控会回退到沉默。预算和效应量应在新队列运行前确定。任务族用 `--holdout-family` 指定，机制用 `--holdout-mechanism` 按冻结源卡的阶段、失败动作签名、替代动作模式分组留出。

主要产物为 `bank.json`、`train-labels.json`、`controller/frozen.json`、`controller/test/live/`、`summary.json`。无有效源记忆、配对不足或单臂各折缺少支持时，结果保留对应分母和回退原因。首轮 ALFWorld 记录按 v1 协议解释。

Terminal-Bench 使用终端任务及其验证器。单题裸 actor 分数用于观察基线；研究问题需要该领域独立历史题构造的源记忆，以及新题上的沉默／提醒干预结果。训练是否提升、是否能观察到提醒致败，都由这些实验量回答。
