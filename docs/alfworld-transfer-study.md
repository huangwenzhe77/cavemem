# ALFWorld 历史记忆迁移实验

主指标是全部沉默成功任务中，加入提醒后失败的比例。所有 274 道官方 TextWorld 游戏实例都进入汇总。研究目标是约 50%，并同时记录救回题、两臂成功时的额外成本和命中覆盖率。以往运行已接触过这一官方队列，本轮用训练区开发游戏做选型，再重新运行官方队列的干预分支。

## 源端和选点

先验证源端的沉默失败、直接修正成功和抽象提醒成功。原样记忆附上真实源目标、观察、修正动作和经环境验证的源成功动作序列，保留源场景里的物体和位置名称。用同一个 Actor 和同一源检查点再跑两次原样记忆，要求两次均成功且净效用都优于源沉默。每份内容可追溯到源文件哈希和新的源回放。

匹配从原始提案出发，只读目标和当前候选。根据目标修饰词与实体相似度找相关源案例，再在第一处具备同类合法候选的状态检索。此前的严格适用条件作为单独的记录字段，可以用来检查匹配时遗漏了哪些状态约束。源场景的建议仍是提示，模型从当前合法候选中选择动作。

## 对照与预算

- 沉默沿用完整官方评测的无记忆轨迹，检查模型、数据清单和排序器版本是否一致。
- 无记忆重拟和原样记忆从同一缓存提案和环境状态分支。两臂都重拟一次，后续决策继续看到各自的提示。两臂采用同一个 50 次调用上限，执行顺序由固定种子为每题确定。
- 另报告按开发区沉默成功题的 token 消耗第 50、75、90 百分位确定的总 token 预算。只有两个重拟提示都能在该预算内完成时才触发。之后在下一次调用超额前停止。Actor 采用单 token 编号选择，预算判定可以从实际运行的提示和轨迹复算。

原样记忆失败且沉默、无记忆重拟都成功的题，提供了提示内容影响结果的配对证据。此处的内容差异包含文字及长度。源证据、命中检查点、每条分支和每个分组的成绩均保存，以便逐题核对。

`alfworld_transfer_audit` 独立读取冻结输入、源端两次回放、沉默轨迹与两条干预分支。它重算全量汇总和按游戏模板聚类的失败率区间，并检查命中时是否满足源端的严格适用条件。

## 逐步复用的对照

`--representation sequence` 将同一条源成功轨迹按检查点对齐。每次后续决策按相对步数取源动作，从当前 Actor 候选中查找同动作结构的合法类比。匹配依次比较原样命令、来源实体及类型的重合。类比以提示提供，Actor 继续从合法候选中决策。历史序列用完时结束提醒。源端按同一逐步规则再次验证。这一对照研究的是目标场景需要额外步骤或变动顺序时，固定源序列还能否适用。

`--representation sequence-trajectory` 在逐步建议之外继续保留完整源轨迹。实验只从训练区开发集选用全量方案。筛选条件为至少 5 道沉默成功题，且提醒致败率落在 40%–60%。多个方案通过时，依次优先采用共同调用预算、提醒失败但无记忆重拟成功的题数、沉默成功分母和距离 50% 的差距。所有开发候选及入选理由保存在选择清单。入选方案在 274 道题上报告四个冻结预算条件。

审计同时列出逐题退化及首个动作。达到 token 上限时失败、放宽至统一 50 次调用后成功的题，另行记录其恢复结果，供分析预算压力的贡献。

预留的 42 道训练区游戏按模板、游戏文件和哈希与原始数据清单做去重。`alfworld_transfer_probe` 可以在这些游戏上复测冻结方案，沿用原预算和同一套无记忆重拟对照。该结果独立记录，正式评测的分母始终使用官方 274 题。

如果需要另测一档服务限额，`alfworld_transfer_budget freeze` 只读取这 42 道训练区游戏的三臂记录，在 35、45、55、65、75、85 百分位形成候选。它会保存所有候选和最终选择。随后 `score` 对已完成、已审计的 274 道题按同一限额重算，逐题截断到下一次调用超额之前。此分析复用正式评测的真实轨迹，报告会标明已有评测暴露，并保留原有四档结果。

原样轨迹的影响会随模型和源数据而变，源端有效的记忆也可能缺少目标场景需要的动作或约束。[MATE 的原样轨迹对照](https://arxiv.org/html/2609.35808) · [WikiTrace 的源证据与回归分析](https://arxiv.org/html/2611.14320)
